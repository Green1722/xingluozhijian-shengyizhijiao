# 板端训练场景切换（实测）

实体板只是语音终端：麦克风、喇叭、4G 联网，**剧情由云端智能体决定**，固件里没有场景表。2026-11-26 在 COM5 上用文本注入实测，云端已支持多个训练场景，切换不需要改固件，也不需要重新烧录。

## 已验证的口令

| 口令（说或注入） | 板子进入的状态 | 实测原文 |
| --- | --- | --- |
| （默认唤醒后） | 小儿静脉输液训练 | 「我是圣医智教的小圣老师，今天我将带你进行小儿静脉输液模拟训练」 |
| 我们开始鼻饲训练 | 鼻饲训练开场 | 「今天我将带你进行鼻饲模拟训练，准备好开始了吗？」 |
| 请扮演患儿家属，我们练习鼻饲操作 | 家属角色扮演 | 「好的，那我扮演患儿家属。医生，你来了，麻烦你看看孩子吧。」 |
| 我想练习鼻导管吸氧，请开始 | 吸氧训练 | 「好，那我们开始鼻导管吸氧训练。现在患儿需要吸氧治疗，请您开始操作吧。」 |

串口命令 `newchat` 可以结束当前会话，让下一个场景从零开始。

## 语音切换的三个前提

1. **先唤醒**：待命状态下要先说「小圣老师」，看到屏幕变化或听到回应，再讲场景口令。日志里对应的行是 `Wake word detected` 和 `StateMachine: State: connecting -> listening`。
2. **场景名说清楚**：现场噪声会干扰识别。实测「我们换个场景，我想练习鼻饲，请开始」被识别成「塑料的收料」，智能体只会回「我没太理解您的意思」。
3. **一次只切一个场景**，切完先等板子把开场白说完，再开始操作。

## 确定性演示：用文本注入代替语音

视频录制或验收时，语音识别不稳定会拖慢节奏，可以直接用 `deploy\record.ps1` 的 `-Ask` 注入文字，板子照样走完整流程：

```powershell
# 鼻饲
.\deploy\record.ps1 -Case "鼻饲（板端实机）" -Seconds 90 -Ask "我们开始鼻饲训练"

# 吸氧
.\deploy\record.ps1 -Case "鼻导管吸氧（板端实机）" -Seconds 90 -Ask "我想练习鼻导管吸氧，请开始"

# 家属角色扮演
.\deploy\record.ps1 -Case "鼻饲家属对话" -Seconds 90 -Ask "请扮演患儿家属，我们练习鼻饲操作"
```

注入走的是 `ask64`（base64 编码的中文），不会出现串口乱码，也不依赖麦克风。

## 与网页训练的分工

| 场景 | 板端 | 网页 |
| --- | --- | --- |
| 小儿静脉输液 | ✅ 云端已配 | 暂未实现 |
| 鼻导管吸氧 | ✅ 云端已配 | ✅ `app.py` 病例 `oxygen` |
| 鼻饲 | ✅ 云端已配 | ✅ `app.py` 病例 `feeding` |

板端负责语音交互和角色扮演，网页负责规则化的对话回放与教师复盘。两边共用同一套回执与复盘格式：板端记录走串口摘录导入，网页记录直接写 `training.sqlite3`。

## 排查

- 录到 0 条对话：先看 `.run\serial.log`，如果只有每 10 秒一条 `SystemInfo: free sram`，说明板子整段时间都在待命，没有被唤醒。
- 板子不回话但日志有 `MQTT: ...` 报错：云端不通，重启板子等网络恢复。
- 板子停在下不来的状态（`waiting for download`）：用的是烧录模式，断电重插即可，不要长时间拉 DTR/RTS。
